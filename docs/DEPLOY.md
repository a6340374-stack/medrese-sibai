Репозиторий: `a6340374-stack/medrese-sibai`. Источник Pages: GitHub Actions. Workflow `.github/workflows/pages.yml` выполняет публичную сборку с адресом из `actions/configure-pages`, проверяет результат и публикует только `dist`. Следующая отправка в `main` автоматически обновляет сайт. Локальная сборка по умолчанию остаётся закрытой от индексации.

Сборщик поддерживает путь проекта `/medrese-sibai`: внутренние ссылки и ресурсы получают этот префикс, canonical и sitemap содержат полный адрес. Проверка ссылок учитывает префикс. robots.txt в каталоге проекта не управляет всем доменом github.io: корневой robots.txt принадлежит корневому сайту аккаунта.

Проверять успешность публикации в Actions и затем по реальным HTTP-ответам сайта. Коммит и push сами по себе не означают успешный деплой.

## Собственный домен

1. Закрыть пункты docs/CONTENT-CHECKLIST.md, согласовать тексты с руководителем.
2. Выбрать домен, владельца и хостинг с HTTPS; реальные контакты сохранить в конфигурации и страницах.
3. Выполнить `python tools/build.py --public --site-url https://ВАШ-ДОМЕН` (подставить реальный домен).
4. Выполнить `python tools/check.py`. Проверить визуально desktop/mobile.
5. Сохранить предыдущую версию и опубликовать содержимое dist. Хостинг должен отдавать /404.html с кодом 404, HTTPS, одно зеркало с редиректом, индекс каталога index.html и корректный UTF-8. Настройка зависит от выбранного хостинга.
6. Проверить настоящие HTTP-статусы, canonical, robots, sitemap, отсутствие noindex и доступность из интернета. Локальная проверка это не подтверждает.
7. Подключить Яндекс Вебмастер и Google Search Console, подтвердить права, отправить sitemap. Региональность подтверждать реальным адресом. Аналитику подключать отдельно после согласования.

Откат: вернуть предыдущий архив dist и настройки хостинга. Собирать новую версию до замены файлов на сервере. Исходники хранить в Git; коммит не означает публикацию.
